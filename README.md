# 🏠 膳待家 Umami

**中文** · [English](README.en.md)

> 把一日三餐、几次训练和一台冰箱，变成一件件能被照顾的小事。

膳待家（Umami）是一个住在本机里的个人健康管家。它不会把你迎接到一张复杂的报表前，而是从一句「今天想先照顾什么？」开始：记下一餐、安排一次运动、称一下体重，或者问团团冰箱里的番茄能做什么。

Umami 基于 [pi](https://github.com/earendil-works/pi) 的 `pi-ai` 与 `pi-agent-core` 构建，使用 Bun + SQLite 驱动。你的健康记录、会话和设置优先留在本机；只有你完成 AI 数据授权并主动使用云模型功能时，完成当前请求所需的内容才会发送给对应的模型提供商。

> ⚡ **还有一个轻量入口**：如果你更喜欢直接在编码助手里聊天，可以使用 [Umami-Skill for Health](https://github.com/renchenxuan/Umami-Skill-for-Health)。想要可视化的冰箱、今日页和团团，用本 Web 版；想要一句话记三餐和排训练，用 Skill 版。

## 它陪你怎样过一天

```text
打开 Umami
    ↓
今日：看一眼状态，知道下一步
    ↓
快速记录：饮食 · 训练 · 体重 · 习惯
    ↓
问团团：把“接下来做什么”说清楚
    ↓
冰箱 / 开小灶：把建议变成一顿饭
```

### 1. 从「今日」开始

桌面端的今日页把热量、训练时长、习惯完成度、体重、最近记录和下一步行动放在同一个厨房驾驶舱里。它只读取本地聚合数据，不会因为打开首页就偷偷调用 AI。

### 2. 只记录一件事

快速记录入口复用原有饮食、训练、体重和习惯表单，不让你重复填写。低风险记录会直接保存，并返回可撤销的「已记录」回执；清空数据、删除收藏、修改偏好等高风险操作仍然需要确认。

### 3. 让团团陪你决定下一步

饭团小厨团团会常驻聊天区，也会出现在今日页的主场景里。你可以问它今天吃什么、怎么练、冰箱里有什么，或让它把一个模糊的健康目标拆成下一步。首次进入时，团团会用一份本地静态三步说明带你认识 Umami；示例对话不会自动发送。

## v4.1：今日仪表盘与可信联动

v4.1 在 v4.0 的本地优先与 AI 授权边界之上，继续把“今日”做成更可靠、更容易使用的入口：

- 🌀 **今日仪表盘**：用四段记录覆盖环、开放式数据行和时间线替代连续指标卡片；点击当前「今日」导航可平滑回到页面顶部。
- 🧭 **移动端任务入口**：固定「今日 · 记录 · 冰箱 · 问团团」四项主导航，饮食、开小灶、训练、健康档案、自动化、技能中心和设置中心统一收进「更多」。
- 📡 **可信读取与失败反馈**：核心页面读取统一经过请求封装，保留错误码、字段错误和请求 ID；刷新失败时保留已有数据，并提供明确重试入口。
- 🧾 **准确的 AI 数据说明**：推荐、冰箱、聊天和定时任务按真实发送字段展示授权范围；聊天和定时任务遵循最小必要读取，不主动携带无关健康记录。
- ♿ **更完整的操作路径**：补齐字段级错误定位、键盘操作、图表文字摘要、触控目标和移动端安全区适配。

## v4.0：可信契约与今日闭环

v4.0 的重点不是再增加一排功能，而是让每一次记录、每一次 AI 调用和每一次首页打开都更可理解、更可控：

- 🔐 **一次授权，全局可控**：聊天、识图、推荐、分析、教程和 AI 保鲜建议统一受全局 AI 数据授权控制。撤销后立即阻止后续模型调用，本地记录仍然可用。
- ✍️ **按风险分层写入**：饮食、训练、体重、习惯、新增食材、收藏和教程等低风险操作自动记录并支持撤销；清空、删除、偏好修改和删除提醒等不可逆或高风险操作先确认。
- 🧳 **可恢复健康数据包**：导出包含完整消息、定时任务、冰箱设置、健康数据和看板状态；导入先预览、自动备份，再以合并方式恢复并修复 ID 冲突引用。任何模型 Key、地图 Key 和系统凭据都不会进入导出包。
- 🏠 **今日闭环**：从「今日状态」到「快速记录」再到「下一步行动」，让应用打开后马上有方向，而不是先面对一块自由拖拽的空白看板。
- 🫶 **团团首次引导**：三步静态引导介绍记录、冰箱、开小灶和问团团；完整说明可从「更多 → 使用说明」或设置中心重新打开。
- 🍃 **厨房驾驶舱视觉**：保留 emerald、极光、食材图片和团团，以首屏团团主场景、状态带、错落式操作模块与记录时间线建立层级；移动端导航和响应式结构保持兼容。

## 功能地图

### 吃饭与冰箱

- 📸 上传冰箱照片，识别食材并保存到本地冰箱
- 🍳 菜谱生成、份量换算、营养估算和三餐记录
- 🛒 购物清单、分区管理、保鲜提醒与 AI 保鲜建议
- 📚 「开小灶」内置 36 道家常菜教程，也支持 AI 生成或自己编辑教程

### 训练与身体

- 🏋️ 按目标、器械和天数生成训练计划与动作指导
- 📏 记录体重、体脂和每日身体数据，查看趋势
- 🎯 管理减脂、增肌、睡眠、饮水等目标
- 💧 打卡睡眠、饮水、心态等日常习惯
- 🗺️ 连接百度、高德或谷歌地图后，规划附近公园、操场和步行/骑行路线

### 团团与工作台

- 🍙 团团桌宠：会等待、打瞌睡、陪你等回复，也会为确认成功欢呼
- 💬 多会话：独立会话、搜索、相对时间、今日/昨天分组和删除
- ⏰ 自动化：用自然语言创建每天、每周或单次提醒，到点写回会话
- 🧩 自由看板：通过「整理看板」访问，拖拽位置和隐藏状态不会被今日页覆盖
- 🌅 动态氛围：极光、蒸汽、光尘、厨房台面剪影和操作成功反馈，支持三档氛围与 reduced-motion

## 隐私与数据边界

Umami 是本地优先应用，但“本地优先”不等于“模型请求永远不出本机”。边界明确写在产品里：

1. **不开通 AI 授权**：可以查看和维护结构化页面、记录健康数据、管理冰箱、导入导出；不会把用户内容发送给模型。
2. **开通 AI 授权后**：只有主动使用对应功能时，必要的数据类别才会发送给当前模型提供商；每个功能会展示数据类别、提供商和估算说明。
3. **撤销授权**：后续聊天、识图、推荐、分析、教程和保鲜建议立即停止；固定的连接测试不携带用户内容，不受此授权影响。
4. **密钥存储**：模型 Key 不写入 SQLite，也不进入导出包。Windows 优先使用 Credential Manager，其他平台使用环境变量回退。
5. **健康边界**：AI 输出是通用健康信息或营养估算，不是医疗诊断；涉及过敏、疾病、药物或紧急情况时应咨询专业人士。

## 快速开始

### 1. 安装依赖

```bash
bun install
```

### 2. 启动

```bash
bun run dev
```

然后打开 <http://localhost:3000>。

### 3. 配置模型

首次进入可以先阅读团团的本地使用说明，不需要 API Key。要使用聊天、识图、推荐、分析、教程生成和 AI 保鲜建议：

1. 打开右上角「设置中心」；
2. 选择模型提供商并填写 API Key；
3. 点击「测试连接」后保存；
4. 在「AI 数据授权」中明确授权携带用户内容发送给模型。

选「自定义（OpenAI 兼容）」时，还需要填写 **Base URL** 和 **模型 ID**。出于 SSRF 与重定向风险，自定义网络端点默认禁用；只有明确设置 `ALLOW_UNSAFE_CUSTOM_ENDPOINTS=true` 后才可使用，且地址必须解析到公网 HTTP(S)，不能指向本机或私有网络。

> 也可以复制 `.env.example` 为 `.env` 预填。请勿提交 `.env` 或 `*.db`。

## 技术栈

- **运行时**：Bun（`bun:sqlite` + `Bun.serve`）
- **Agent 框架**：`@earendil-works/pi-agent-core`
- **统一 LLM 接口**：`@earendil-works/pi-ai`
- **数据存储**：SQLite
- **前端**：原生 HTML / CSS / JavaScript，桌宠使用本地精灵图渲染

## 架构要点

- **结构化页面不依赖模型**：食材、训练、饮食、身体资料和本地导入导出在无 Key 或断网时仍可使用。
- **Agent 负责智能部分**：识别食材、生成菜谱/训练计划和通用健康信息；不提供医疗诊断或治疗建议。
- **工具负责确定性副作用**：读写 SQLite、营养计算、提醒和可撤销 Action 都由本地工具完成。
- **会话隔离与恢复**：每个会话持久化消息并拥有独立 Agent 上下文；请求开始时使用当前模型配置快照。
